# 취약 비밀번호 차단 기능 구현·검증 보고서

- 작성일: 2026-07-23
- 적용 범위: 회원가입, 비밀번호 재설정, 인증 API 계약
- 요구사항: `AUTH-004`, `AUTH-010`, `SEC-001`
- 테스트: `SEC-AUTH-009`

## 1. 문제와 위험

기존 구현은 비밀번호 길이만 12자 이상으로 제한했다. 따라서 대문자·숫자·특수문자
누락, 흔한 비밀번호, 키보드·숫자 연속 문자열, 계정 식별자를 포함한 비밀번호도
가입 요청으로 제출할 수 있었다. 화면 검사만 추가하면 직접 API 호출로 우회할 수
있고, 재설정 경로에 같은 정책을 적용하지 않으면 이미 가입한 계정에서 취약한
비밀번호로 되돌릴 수 있다.

## 2. 변경 내용

서버가 다음 조건을 모두 검증하도록 공통 정책을 추가했다.

- 12~128자
- 영문 대문자, 영문 소문자, 숫자, 공백이 아닌 특수문자를 각각 1자 이상 포함
- `password`, `qwerty`, `admin` 등 흔한 문자열을 위치와 관계없이 거부
- `123456`, `654321`, `abcdef`, `fedcba`, 키보드 연속 문자열을 거부
- 같은 문자 4회 이상 연속 사용을 거부
- 이메일 아이디 또는 8자리 이상 휴대전화 번호가 비밀번호에 포함되면 거부

회원가입과 비밀번호 재설정 API는 위반 시 HTTP 400과 안전한 오류 코드
`WEAK_PASSWORD`를 반환한다. 검증은 계정 생성·비밀번호 해시 계산·재설정 코드
소비보다 먼저 수행하므로 취약한 값이 DB에 저장되지 않고, 취약한 새 비밀번호를
입력해도 유효한 재설정 코드는 소모되지 않는다.

회원가입과 재설정 화면에는 각 조건의 상태를 체크(`✓`)/엑스(`✕`)로 표시했다.
색상만으로 상태를 구분하지 않으며 화면낭독기에는 `충족`/`필요` 상태를 제공한다.
화면은 제출 전에 구체적인 보완 항목을 안내하지만, 최종 보안 판단은 항상 서버가
수행한다. 입력란은 `aria-describedby`와 `aria-invalid`로 안내 목록과 연결했다.

OpenAPI, 제품 요구사항, 페이지 설명, 테스트 계획과 추적표도 동일 정책으로
갱신했다. 기준선은 89개 요구사항으로 재검증했다.

## 4. 잔여 위험과 유지보수

현재 흔한 비밀번호 검사는 코드에 포함한 보수적 목록과 패턴을 사용한다. 대규모
유출 비밀번호 전체 목록을 검사하는 기능은 아직 없다. 운영 보안 수준을 더 높일
때에는 원문 비밀번호를 외부로 전송하지 않는 오프라인 유출 목록 또는 k-익명
접두 해시 조회를 추가하고, 외부 조회 장애 시 정책과 개인정보 영향평가를 먼저
확정해야 한다.

정책을 변경할 때에는 서버와 화면의 테스트 벡터, `AUTH-010`, OpenAPI와
`SEC-AUTH-009`를 같은 변경에서 갱신한다. 기존 회원의 비밀번호는 이번 배포로
강제 만료하지 않으며, 이후 비밀번호 재설정 시 새 정책을 적용한다.
