# F4 결제·내구성·출시 준비 검토 기록

작성일: 2026-07-21  
대상: WBS-04 운영 경계, WBS-05~10 잔여 구현  
상태: 검토중

## 구현 결과

- 메모리 결제 전용 구조를 설정 가능한 Toss HTTP API와 Payment Widget SDK v2 경계로 확장했다.
- 웹훅에 전송 시각·HMAC 검증을 추가하고 raw body와 outbox를 단일 DB 트랜잭션으로 저장한다.
- 워커가 outbox를 claim, 지수 backoff, stale claim 회수, 10회 dead-letter 정책으로 처리한다.
- 구매확정 후 7일 정산 보류, 분쟁 중지, 지급 브리지, 정산 원장과 실패 재시도를 구현했다.
- 관리자에게 결제·웹훅·정산 조회, 제공자 대사, outbox 재처리와 재인증 감사 경계를 추가했다.
- Redis Socket.IO adapter, 연락처 전달 webhook, 인증 코드 재발급 제한, OTLP exporter와 운영 경보를 추가했다.
- 두 사용자가 상품 등록부터 에스크로 승인·인도·구매확정까지 수행하는 Playwright 여정을 추가했다.

## 외부 확인이 필요한 항목

코드로 대체할 수 없는 실제 Toss 계정, 연락처·지급 공급자, 실기기 접근성, 장애·복구
훈련은 `user-test-checklist.md`에 절차와 통과 기준을 기록했다. 이 항목은 구현 완료를
막지 않지만 실제 출시 판정을 위해서는 수행 증거가 필요하다.

## 자동화 검증 결과

2026-07-21의 최종 소스 기준으로 다음 게이트를 통과했다.

- PostgreSQL 18 새 데이터베이스에 migration 9개 적용
- build, lint, typecheck, 보안 기준선 검사 통과
- 단위 테스트 22건, 통합 테스트 14건, OpenAPI 계약 테스트 6건 통과
- 기준선 산출물 8개와 요구사항 88개 검증 통과
- Playwright 22건 통과: Axe·보안 헤더와 두 사용자 에스크로 거래 전체 여정 포함
- 일반 조회 성능 smoke 80회/동시 10회: 실패 0, P95 147ms (기준 1,000ms)

성능 수치는 로컬 컨테이너 smoke 결과이며 실제 운영 용량 판정을 대신하지 않는다.

## 판정

기능 구현은 출시 후보 검토 단계로 전환할 수 있다. 자동화 게이트 통과와 외부 사용자
테스트 증거가 모두 확보된 이후에만 WBS-10과 전체 프로젝트를 `완료`로 전환한다.
