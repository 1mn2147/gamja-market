## 1. 결론

현재 구현된 회원·인증, 상품·검색, 실시간 채팅, 신고·차단, 거래, 에스크로
샌드박스 결제, 취소·분쟁, 관리자, 감사, 상태 점검 기능을 실제 브라우저와 API로
사용하고 PostgreSQL 저장 결과까지 대조했다. 최종 종합 실사용 시나리오는 14.2초에
통과했고, 수정 반영 후 전체 `test:release`도 통과했다.

시험 중 실제 결함 2건을 발견했다.

1. 관리자 결제 목록의 중첩 `BigInt` 직렬화 실패로 `/admin/payments`가 500을
   반환했다.
2. Redis 장애 중 readiness 클라이언트가 계속 재접속해 `/readyz`가 응답하지 않았다.

두 결함을 수정하고 각각 자동 회귀 테스트와 실제 런타임 재시험을 통과했다. Redis
복구 후 Worker도 재시작 없이 5초 이내 Outbox를 정확히 1회 처리했다.

실제 Toss 계정, 이메일·SMS 공급자, 지급 공급자, 실기기·스크린리더, 운영 백업
복원은 로컬 환경에서 대체할 수 없으므로 `docs/user-test-checklist.md`의 필수 외부
시험으로 남아 있다. 따라서 이 보고서의 통과 판정은 현재 구현과 로컬 샌드박스에
대한 것이며 실제 운영 배포 승인을 의미하지 않는다.

## 7. 발견 결함과 수정

### DFT-001 관리자 결제 목록 500 — 수정·통과

- 영향: `ADMIN-002`, `ADMIN-005`, 운영 결제 조회
- 원인: 결제 금액은 문자열로 변환했지만 중첩된 거래의 `priceKrw`가 JavaScript
  `BigInt` 상태여서 Nest 응답 직렬화가 실패했다.
- 수정: `apps/api/src/admin/admin.service.ts`에서 중첩 거래 금액도 문자열 DTO로
  변환했다. 결제 키 마스킹은 유지했다.
- 회귀 방지: `API-ADMIN-009`를 추가해 결제 금액과 중첩 거래 금액이 모두 문자열로
  반환되는지 검증했다.
- 재시험: 관리자 통합 테스트 3건, 관리자 화면, `/admin/payments` 200 통과.

### DFT-002 Redis 장애 readiness 무응답 — 수정·통과

- 영향: 가용성·장애 격리, 이전 보고서의 PD-001
- 원인: readiness의 일회성 Redis 클라이언트가 연결 제한 시간 이후에도 기본
  재접속을 계속했다.
- 수정: `apps/api/src/readiness.service.ts`의 readiness 전용 Redis 연결에
  `reconnectStrategy: false`와 2초 연결 제한을 함께 적용했다.
- 회귀 방지: readiness 단위 테스트에서 bounded probe 구성을 검증한다.
- 재시험: Redis 중단 상태에서 10ms 내 HTTP 503과
  `DEPENDENCY_UNAVAILABLE`, 재기동 후 두 번째 확인에서 200.

### 이전 PD-002 Worker 자동 복구 — 재시험 통과

Redis 중단·복구 후 Worker 프로세스를 재시작하지 않고 테스트 Outbox 이벤트를
삽입했다. 5초 내 `PROCESSED`, `attempts=1`이 되어 자동 재연결과 정확히 한 번의
처리를 확인했다.

중복 전송 ID 거부를 확인했다. 로컬 Worker에는 실제 공급자 시크릿이 없으므로 해당
이벤트는 `PAYMENT_PROVIDER_NOT_CONFIGURED`로 재시도됐다. 이는 외부 설정이 없는
환경의 예상 결과이며, 실제 배포에서는 UT-EXT-001 통과 전까지 승인할 수 없다.

P1인 활성 세션 개별 관리, 상품 임시저장, 최근 검색 저장, 채팅 알림 설정, 제재
이의제기는 현재 구현 기능 범위에서 제외했다. 이 항목은 출시 후 개선 범위이므로
이번 현재 기능 통과 수치에 포함하지 않았다.

## 9. 최종 판정

현재 구현된 로컬 기능과 보안·데이터 무결성·성능·Redis 복구 게이트는 통과했다.
시험에서 발견한 두 결함도 수정 후 전체 회귀를 완료했다. 개발 환경에서 기능 검토를
계속 진행할 수 있고 로컬 출시 후보 상태는 `GO`다.

실제 운영 배포는 `docs/user-test-checklist.md`의 외부 필수 시험 5종과 운영 비밀
주입(`AUTH_DEBUG_CODES=false`, `COOKIE_SECURE=true`, 실제 Toss·연락처·지급 키),
백업 복원·경보 증거를 확보한 뒤 최종 `GO`를 판정한다.
