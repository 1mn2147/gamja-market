# 출시 차단 결정대장

아래 항목은 코드로 임의 확정할 수 없다. 결정값이 승인되면 관련 WBS, API,
테스트와 화면 문구에 반영한다. 책임자는 역할이며 실제 담당자와 기한은
프로젝트 오너가 관리한다.

| ID | 결정 필요 사항 | 결정값 | 상태 | 후속 작업 |
| --- | --- | --- | --- | --- |
| DEC-01 | Toss 계약, MID, 에스크로·지급대행 범위, 판매자 본인확인 | Toss sandbox와 테스트 UI까지만 구현한다. 실결제·실정산은 포함하지 않는다. | 승인 | 결제 모듈은 sandbox adapter와 fixture만 사용한다. 실결제 키·MID·지급 호출은 추가하지 않는다. |
| DEC-02 | 분쟁 최종 조정 권한과 증빙 보존 기간 | 최고관리자 1인이 분쟁을 최종 처리한다. | 승인 | 관리자 권한과 감사 로그로 분쟁 최종 명령을 보호한다. 증빙 보존 기간은 DEC-04를 따른다. |
| DEC-03 | 고위험 관리자 작업 승인 절차 | 추가 승인자는 두지 않는다. 최고관리자 재인증과 사유 기록만 요구한다. | 승인 | 수동 고위험 명령은 재인증·사유·변경 전후 감사 로그를 필수로 한다. |
| DEC-04 | 개인정보·채팅·거래·감사 로그 보존 기간 | 로그는 2년 보관한다. 개인정보·채팅·거래 데이터는 탈퇴 후 1년까지 보관한다. 감사 로그를 포함한 로그는 생성 후 2년 보관한다. | 승인 | 보존 기한·삭제/익명화 정책, 법적 보존 예외, 복구 불가능한 삭제 절차를 구현·테스트한다. |
| DEC-05 | 정상 부하량·지원 기기 기준 | 소규모 웹사이트 기준으로 우선 구현한다. | 방향 승인 | 부하·동시 사용자·지원 기기의 수치 기준은 성능 판정 전 별도 확정한다. 수치 없는 측정값은 참고치다. |
| DEC-06 | 초기 상품 이미지 저장소 | 소규모 서비스 단계에서는 검증한 이미지 바이트를 PostgreSQL에 저장한다. | 승인 | 용량·트래픽 측정값이 운영 한계를 보일 때 S3 호환 비공개 객체 저장소와 사전 서명 업로드를 ADR로 재검토한다. |

## 승인 기록 형식

승인된 결정은 다음 항목을 변경 이력으로 계속 관리한다.

- 결정값과 적용 환경
- 근거 문서·계약 또는 법무 검토 기록
- 승인자·승인 시각·재검토 시점
- 영향을 받는 WBS, API, 데이터 모델, 화면 문구, 테스트 ID
- 롤백 또는 계약 변경 시 대응

## 현재 구현 제한

- 실제 Toss 비밀값, MID, 카드 정보, 실결제·실정산 호출을 저장하거나 추가하지 않는다.
- 분쟁은 지정된 최고관리자의 재인증된 도메인 명령으로만 처리하고, 상태를 직접 덮어쓰지 않는다.
- 데이터 삭제·익명화는 탈퇴 후 1년, 로그 삭제는 생성 후 2년 이전에는 실행하지 않는다.
- DEC-05의 수치 기준이 정해지기 전에는 성능 측정값을 출시 통과 근거로 선언하지 않는다.
- 초기 상품 이미지는 DEC-06에 따라 PostgreSQL에 저장하며, S3 전환은 측정 근거와 별도 ADR 없이 진행하지 않는다.
