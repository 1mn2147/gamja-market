# 기능 패치 및 검증 보고서

## 1. 범위와 판정

- 대상: 비밀번호 재설정, 채팅, 상품 카드 레이아웃, 상품 삭제, 부분 일치 검색,
  거래 요청 후 채팅 이동, 회원 탈퇴 시 상품 처리
- 요구사항 기준: `AUTH-004~005`, `ITEM-002`, `ITEM-007`, `SEARCH-001`,
  `CHAT-001`, `CHAT-003`, `PAY-001`, `SEC-002~005`
- 테스트 기준: `docs/test_plan.md`의 회원·상품·검색·채팅·거래 및 보안 게이트
- 환경: Docker Compose의 PostgreSQL 18, Redis 8, NestJS API, Next.js Web,
  Playwright Chromium
- 최종 판정: 로컬 출시 후보 `GO`

실제 운영 배포는 연락처 전달 공급자, 운영 Web Origin, 운영 비밀과 다중 브라우저
수동 시험을 별도로 통과해야 한다.

### 패치 직접 회귀 시나리오

- 구매자가 상품에서 거래를 요청하면 채팅 상세로 이동하고 `REQUESTED` 거래 링크가
  표시된다.
- 구매자와 판매자가 각각 메시지를 전송하고, 새로 방을 연 상대방 화면에서도
  저장된 메시지가 보인다.
- 판매자 수락부터 결제, 인도, 구매확정까지 진행한 결과가
  `Trade=CONFIRMED`, `Product=SOLD`, `Payment=APPROVED`로 저장된다.
- 비밀번호 재설정 후 이전 세션은 401이 되고 새 비밀번호 로그인은 성공한다.
- 95자 제목과 502자 연속 문자열 설명을 가진 카드의 `scrollWidth`가
  `clientWidth`를 넘지 않는다.
- 소유자가 상품을 삭제하면 내 목록에서 사라지고 공개 API는 404를 반환한다.
- `프리미엄 자색 감자`를 `리미 자색`으로 검색해 찾는다.
- 회원 탈퇴 후 판매중 상품은 `HIDDEN`이 되고 공개 API는 404를 반환한다.
- 활성 거래 요청이 있는 상품의 삭제는 409
  `PRODUCT_LOCKED_BY_ACTIVE_TRADE`로 거부된다.

## 4. PostgreSQL 직접 대조

최종 브라우저 실행 데이터를 API 응답뿐 아니라 PostgreSQL에서 직접 조회했다.

| 흐름 | DB 결과 |
| --- | --- |
| 전체 거래 여정 | 거래 `CONFIRMED`, 상품 `SOLD`, 결제 `APPROVED`, 채팅 참가자 2명, 메시지 2건 |
| 비밀번호 재설정 | 사용자 `ACTIVE`, 폐기 세션 1개, 새 활성 세션 1개, 비밀번호 해시 접두사 `$argon2id` |
| 상품 삭제 | 상품 행 `DELETED` 유지, 공개 조회 404 |
| 부분 검색 | 검색 대상 상품 `ACTIVE` |
| 회원 탈퇴 | 사용자 `WITHDRAWN`, 상품 `HIDDEN` |

## 5. 시험 중 발견 사항

1. 채팅 상세에 링크를 추가하면서 `next/link` import가 빠져 최초 빌드가 실패했다.
   import를 추가한 뒤 전체 빌드와 타입 검사가 통과했다.
2. E2E에서 “메시지” 입력과 “읽지 않은 메시지” 배지가 같은 접근성 문자열 일부를
   공유했고, 공통 헤더와 본문에 각각 상태 영역이 있었다. 테스트 선택자를 정확한
   textbox와 `main` 상태 영역으로 한정했다.
3. 짧은 시간 안에 반복 재시험하면서 개발 API의 분당 100요청 전역 제한이 정상
   동작해 후속 인증 조회가 429가 됐다. 새 제한 시간 창에서 전체 릴리스 게이트를
   다시 실행해 29건 모두 통과했으며, 제품 결함으로 판정하지 않았다.

## 6. 잔여 위험과 운영 전 필수 시험

- 로컬 환경은 `AUTH_DEBUG_CODES=true`라 재설정 코드를 화면에 보여 준다. 운영은
  반드시 `false`로 설정하고 실제 이메일/SMS 전달·만료·재전송을 검증해야 한다.
- 운영 Web Origin과 Socket.IO CORS, HTTPS/WSS, 프록시 유휴 시간 제한에서
  재연결·REST 대체 저장을 재시험해야 한다.
- 현재 부분 문자열 검색은 정확성이 우선인 구현이다. 상품 수가 커지면
  PostgreSQL trigram 인덱스와 실데이터 부하 시험을 추가한다.
- Firefox, WebKit, 모바일 실기기, 키보드와 스크린리더 수동 검증은 별도 사용자
  테스트 체크리스트에서 수행한다.
- 실제 Toss 승인·환불·웹훅과 지급 공급자 연결은 로컬 샌드박스 통과만으로
  운영 승인할 수 없다.
