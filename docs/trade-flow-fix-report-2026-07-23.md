# 거래 구매 정상 흐름 보완 보고서

- 작성일: 2026-07-23
- 대상: 복수 구매 요청, 에스크로 결제 전 인도, 미결제 예약 잠금, 거래 상태 안내
- 기준: `docs/requirements.md`, `docs/test_plan.md`, `docs/page_desc.md`

## 1. 수정 결과

구매 정상 흐름을 다음과 같이 고정했다.

`거래 요청 → 판매자 수락·상품 예약 → 에스크로 결제 → 인도 완료 → 구매 확정 → 7일 정산 보류 → 정산`

판매자가 한 요청을 수락하면 동일 상품의 다른 `REQUESTED` 거래는 같은 DB
트랜잭션에서 `REJECTED`로 바뀌며
`PRODUCT_RESERVED_BY_ANOTHER_TRADE` 사유와 상태 이력이 저장된다. 따라서 예약된
상품에 처리할 수 없는 요청이 계속 남아 구매 가능 상태로 오인되는 문제를
제거했다.

## 2. 서버와 데이터 정합성

### 2.1 경쟁 구매 제어

- 상품의 `ACTIVE → RESERVED` 전환과 선택 거래의 `REQUESTED → ACCEPTED` 전환을
  원자적으로 처리한다.
- 경쟁 요청의 거절과 이력 생성도 같은 트랜잭션에 포함한다.
- 두 수락 요청이 동시에 도착해도 한 요청만 성공하도록 통합 테스트를 추가했다.

### 2.2 미결제 예약 해제

- 결제 승인 전에는 구매자와 판매자 모두 거래를 취소할 수 있다.
- 수동 취소 시 상품을 `ACTIVE`로 복원하고 `READY`, `UNCONFIRMED`, `FAILED`
  결제 주문은 `CANCELLED/PAUSED`로 함께 정리한다.
- 판매자 수락 후 결제 주문이 생성되지 않은 채 7일이 지나면 worker가 거래를
  자동 취소하고 상품 예약과 상태 이력을 한 번만 갱신한다.
- 결제 주문 생성과 자동 만료가 경합하지 않도록 거래 행 잠금을 사용한다.

### 2.3 결제 취소 기간

승인된 결제의 취소 기한을 거래 생성일이 아니라 `Payment.approvedAt`부터
7일로 계산하도록 변경했다. 승인 결제는 거래 취소 API로 우회할 수 없고 결제
취소 API를 통해서만 처리된다.

### 2.4 기존 데이터 보정

두 데이터 마이그레이션을 적용했다.

1. 이미 예약·판매된 상품에 남아 있던 경쟁 요청을 사유 있는 `REJECTED`로 정리
2. 취소 거래에 남아 있던 미승인 결제 주문을 `CANCELLED/PAUSED`로 정리

보정은 금전 승인이 없는 주문에만 적용되며 결제 원장 금액은 변경하지 않는다.

## 3. 거래 화면

- 거래 상세 응답에 당사자에게만 공개되는 안전한 결제 요약을 포함했다.
- 판매자는 `Payment=APPROVED`일 때만 `인도 완료로 표시` 버튼을 볼 수 있다.
- 결제 전에는 결제 대기 안내와 7일 기한을 표시한다.
- 구매자가 이미 `READY` 주문을 만든 경우 새 주문을 만들지 않고 기존 결제
  상세로 돌아갈 수 있다.
- 거래·결제 상태를 한글로 표시한다.
- 서버 오류 코드를 그대로 노출하지 않으면서 경쟁 거래, 결제 선행 조건,
  결제 취소 경로와 기한을 구분해 안내한다.

기존에 수락됐던 두 번째 거래가 사용자에 의해 취소되었기 때문에 현재 관리자
요청은 다시 수락 가능한 상태다. 판매자가 현재 요청을 수락하면 상품이 예약되고,
관리자 구매자 화면에 에스크로 결제 행동이 나타난다.
