# 사용자·외부 시스템 검증 체크리스트

자동화만으로 확정할 수 없는 항목을 기록한다. 구현과 자동화 검증은 이 문서의
승인을 기다리지 않고 계속 진행하며, 출시는 아래 `필수` 항목의 증거가 있어야 한다.

## 증거 작성 규칙

- 실행 일시, 환경, 수행자, 빌드 식별자를 기록한다.
- 카드번호, 결제 키, 연락처 원문, 비밀번호와 비밀 키는 캡처하거나 첨부하지 않는다.
- 실패 시 관찰한 화면 문구, 안전하게 마스킹한 요청 ID, 기대 결과와 실제 결과를 남긴다.
- 결과는 `통과`, `실패`, `조건부 통과` 중 하나로 기록한다.

## UT-EXT-001 실제 Toss 테스트 결제 — 필수

준비:

1. Toss 개발자 콘솔의 테스트 클라이언트 키·시크릿 키와 웹훅 비밀을 준비한다.
2. `TOSS_SANDBOX_MODE=false`, `NEXT_PUBLIC_PAYMENT_SANDBOX_MODE=false`로 설정한다.
3. `TOSS_SANDBOX_SECRET_KEY`, `NEXT_PUBLIC_TOSS_CLIENT_KEY`, `TOSS_WEBHOOK_SECRET`을 비밀 저장소로 주입한다.

절차:

1. 구매자와 판매자로 로그인해 상품 등록, 거래 요청, 수락까지 진행한다.
2. Toss 결제창에서 테스트 카드로 승인한다.
3. 성공 리다이렉트 후 결제 금액·주문 ID·상태가 일치하는지 확인한다.
4. 같은 승인 URL을 새로고침하고 원장 항목이 하나인지 확인한다.
5. Toss 콘솔에서 같은 웹훅을 재전송하고 중복 처리되지 않는지 확인한다.
6. 잘못된 금액, 만료된 전송 시각, 잘못된 서명의 요청이 거부되는지 확인한다.
7. 취소와 환불을 각각 수행하고 내부 원장 합계가 0인지 확인한다.

통과 기준: 카드 원문이 애플리케이션 로그·DB·큐에 없고, 승인·취소·환불 및 중복
웹훅 결과가 Toss 조회 결과와 일치한다.

## UT-EXT-002 연락처 전달 공급자 — 필수

1. 이메일 또는 SMS 중 선택한 공급자를 `CONTACT_DELIVERY_WEBHOOK_URL`에 연결한다.
2. 정상 발송, 잘못된 서명, 공급자 5xx, 5초 타임아웃을 각각 시험한다.
3. 발송 실패 후 `/auth/contact-confirmations/request`로 재요청한다.
4. 10분 내 4번째 요청이 429가 되는지 확인한다.

통과 기준: 인증 코드는 의도한 연락처에만 전달되고 로그에 남지 않으며, 장애 후
재요청으로 가입을 완료할 수 있다.

## UT-EXT-003 지급·정산 공급자 — 필수

1. 지급 서비스 브리지를 `SETTLEMENT_PAYOUT_WEBHOOK_URL`에 연결한다.
2. 구매확정 7일 전에는 지급 요청이 없는지 확인한다.
3. 7일 경계 후 동일 `idempotency-key`로 한 번만 지급되는지 확인한다.
4. 분쟁 상태에서는 지급이 중지되는지 확인한다.
5. 공급자 5xx 후 `FAILED` 상태와 재시도를 확인한다.

통과 기준: 판매자 지급액이 승인액을 넘지 않고, 원장에 정산 항목이 한 번만 추가되며,
분쟁·환불 거래는 지급되지 않는다.

## UT-UX-001 실기기·키보드·스크린리더 — 필수

대상: 모바일 Safari, 모바일 Chrome, 데스크톱 Chrome·Firefox, NVDA 또는 VoiceOver.

1. 가입부터 상품 등록, 검색, 채팅, 거래, 결제, 신고까지 키보드만으로 수행한다.
2. 320/768/1024/1440px에서 가로 스크롤, 가림, 예기치 않은 레이아웃 이동을 확인한다.
3. 오류·연결 끊김·결제 확인 중 상태가 스크린리더로 한 번만 명확히 안내되는지 확인한다.
4. 모든 조작 대상이 최소 44px이고 초점 표시가 보이는지 확인한다.

통과 기준: 핵심 여정을 막는 WCAG 2.2 AA 결함이 없고, 자동 Axe 결과와 수동 결과를 함께 보관한다.

## UT-OPS-001 장애·복구 훈련 — 필수

1. API 실행 중 Redis를 2분 중단하고 복구한다.
2. 워커를 웹훅 수신 직후 중단한 뒤 재시작한다.
3. PostgreSQL 백업을 별도 DB에 복원하고 원장·감사 로그 개수를 비교한다.
4. 결제 제공자 타임아웃과 outbox dead-letter를 발생시키고 관리자 화면에서 재처리한다.

통과 기준: 데이터 유실이나 중복 정산 없이 복구되고, 경보·운영 절차·감사 로그가 남는다.
